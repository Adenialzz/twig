# twig 全局 Console 设计与实施方案

状态：2026-10-19 用户确认，开始实施。本文区分产品约定、实现方案与验证结论；实际使用说明见 [README](../README.md)。

## 1. 目标与边界

任意目录执行裸 `twig`，浏览全局登记的项目与任务，选择进入 Shell，查看工作目录下 Codex 会话的真实状态。基础环境管理独立于 Codex；Codex 为可选的只读观察能力。

首版包含全局浏览、搜索、进入、Git/tmux 状态、Codex 多会话详情和分页历史查询。已追加项目登记与任务创建表单；已追加任务删除确认；停止、PR/MR 继续使用现有命令；不提供审批、发送消息、恢复会话、启动 Agent、自动合并、Diff 编辑和常驻 Sidebar。退出界面不影响已有 Shell 和 Agent。

## 2. 命令入口

- `twig` 与 `twig console`：全局 Console，不要求调用目录为 Git 仓库。
- `twig --repo NAME`：显示全局列表并定位 NAME，不隐藏其他项目。
- `--config PATH`：遵循已有登记表选项，相对路径基于调用目录解析。
- 无 `--repo` 时按调用目录定位最深匹配的已登记工作目录；否则按名称选第一项。
- 原子命令语义保持不变。非交互 stdin/stdout 直接报错，脚本使用明确子命令。
- 登记表不存在显示空页面与 `twig init` / 登记提示，不创建文件或锁。未知显式项目名明确报错。
- 补全在 Console 分流之前处理，只读且不启动 TUI。

## 3. 界面与交互

宽终端左侧为项目列表，右侧从上到下依次为任务列表、Codex 会话列表、详情，共四个可见区域。Tab/Shift+Tab 只在项目、任务、会话三个列表之间切换焦点；详情不单独获取焦点，用 PgUp/PgDn 滚动。窄终端按焦点显示项目页、任务页或会话页，会话页同时显示会话列表与详情。顶部为全局项目、任务和 Codex 计数；底部为按键、连接状态和错误，正常刷新时不显示秒数。

项目列表：别名、登记任务数量、Codex 状态数量、异常。任务列表：固定主工作目录行，随后按名称排列的 twig 任务；分支、Git 状态、窗口状态、Codex 摘要。详情：实际路径、期望与实际分支、读取错误、会话列表与选中会话完整信息。

按键：上下或 j/k 移动；Tab/Shift+Tab 切区；Enter 在项目区切到任务列表并选中主工作目录、任务区进入任务、会话区展开详情；/ 搜索当前列表；Esc 清空搜索或返回；r 刷新；h 切换已加载/历史会话；n 在项目区登记仓库、任务区新建任务、会话区加载下一页历史；a 切换历史查询包含子目录；? 帮助；PgUp/PgDn 滚动详情；q/Ctrl+C 退出。

搜索匹配项目别名、任务名/分支、会话标题/ID。按名称稳定排列项目与任务，选中项用稳定标识跟踪，刷新不抢焦点。会话按状态优先级与 ID 稳定排序。来源和 ID 同时展示，避免多个同名会话混淆。

主窗口和任务进入时重新读取配置、检查 Git 与 tmux 归属。缺失窗口按 open 语义重建 Shell；Worktree 缺失不自动重建代码。锁在 attach 前释放。恢复终端后执行 tmux attach/switch-client；进入调用返回后恢复 Console 并重启采集，保留选择和焦点；失败时显示错误。普通终端 attach 阻塞直到 detach，随后返回面板；tmux 内 switch-client 返回后面板继续留在原窗口，切回即可使用。

会话与 Pane 没有可靠一一映射；选会话只看详情，不按目录猜测 Pane，不恢复会话。

## 4. 状态语义与归属

项目来自登记表，不扫描磁盘找仓库。任务来自共享 Git 目录的状态记录；Git/tmux 查询决定实际状态。路径不存在、未初始化、配置损坏、分支变更、归属冲突单独显示；坏项目不阻止浏览其他项目。

Git 摘要区分暂存、未暂存、未跟踪数量，干净遵循普通 Git status，不含 ignored 文件；不等同满足删除条件。窗口存在不表示 Codex 存在。主目录行不算任务数。

Codex thread.id 是唯一标识。路径规范化后优先匹配最深工作目录，组件级比较，支持从子目录启动，避免字符串前缀误匹配。不能规范化的路径不猜测归属。嵌套项目归属最深目录；外部目录不纳入全局计数。子会话展示父会话 ID，按会话计数而非任务计数。

| 协议状态 | 文案 |
| --- | --- |
| active，标记为空 | 运行中 |
| active + waitingOnApproval | 等待审批 |
| active + waitingOnUserInput | 等待输入 |
| 同时两个标记 | 同时显示两种等待 |
| idle | 空闲 |
| notLoaded | 当前服务未加载 |
| systemError | 会话错误 |
| 未认识的状态或标记 | 原值与未知状态提示 |
| 请求失败、断开 | 未知；旧数据明确标记过期 |

空闲不是本轮完成，轮次完成不是开发任务完成。线程 updatedAt 是记录更新时间，不冒充状态持续时间。模型/推理强度为当前配置或保存值，不冒充逐轮遥测。

默认排除 `ephemeral=true` 的临时会话，不进入已加载/历史列表或状态统计；不按空标题猜测，不删除或关闭服务中的会话。历史扫描进度仍统计实际读取的记录数。

## 5. Codex 数据与协议

连接本机已有 app-server，通过 `codex app-server daemon version` 的 JSON 发现 socket，不硬编码安装路径，不创建或重启服务。使用 UnixStream 上的标准 WebSocket 握手，再进行 initialize/initialized；不把 proxy 当作逐行 JSON 协议转换器。

首个实测版本 0.163.0。版本用于诊断，协议不兼容明确报错。只实现所需字段，其余字段允许扩展；必需字段缺失或格式错误报错。

只读调用：thread/loaded/list、thread/read(includeTurns=false)、thread/list(useStateDbOnly=true)、thread/turns/list(itemsView=notLoaded)。不调用 start/resume/fork/turn/start、审批或修改元数据，不直接读取 Codex 数据库/会话日志。

活动发现：完整分页读取 loaded/list，缓存 ID 到线程概要；每轮重新读取状态，按 twig 工作目录关联。所有已加载会话都可能 idle，不称作全部正在运行。

历史：默认精确 cwd 查询并分页；显式包含子目录时分批扫描元数据并本地过滤，显示扫描进度，每页由用户继续，可取消。不会在启动时全量扫描历史。历史与活动合并时按 ID 去重；已加载会话以最近实时查询为准。

会话字段：名称/首条提示摘要、完整 ID、cwd、来源、模型、推理强度、创建和更新时间、父会话。选中详情才按需请求最新一轮的状态、开始/完成时间和错误；不加载完整对话正文。

会话创建、更新时间显示为北京时间（固定 UTC+8）的 YYYY-MM-DD HH:mm:ss，并标注时区；更新时间指会话记录更新时间，不是面板刷新时间。轮次详情中的时间字段仍按服务返回值展示。

第一版轮询状态快照，不依赖未经验证的全局通知订阅，不为订阅执行 resume。断开后清理连接，重新发现、握手；旧结果保留但标明过期。服务缺失时导航仍可用。连接只在本机 socket，不使用 HTTP 代理，也不改变 Codex 联网配置。

## 6. 刷新、并发与失败

目标节奏：登记表/任务记录 10 秒；tmux 与 Codex 2 秒；当前项目 Git 5 秒；历史与轮次按需。轮次完成后再计间隔，请求不叠加、不堆积。只查询选中项目的详细 Git 状态，其他项目保留已采集值和时间。

正常时不展示距上次采集的秒数；Git/Codex 超过 30 秒未成功更新时显示固定的「状态过期」，查询失败立即提示异常。提示不逐秒跳动，按 r 可请求刷新。

一个主线程处理渲染与输入，一个采集线程顺序执行阻塞查询；使用标准库 channel 和取消标记，无异步运行时、无后台守护进程。慢查询不阻塞键盘。切换选择淘汰过期请求，所有命令/socket 请求设置超时。退出取消查询并回收子进程。采集失败单独标记数据源与最后成功时间，禁止静默把错误解释成空列表/空闲。

刷新不获取项目/登记锁，不创建配置，不改变进程 cwd，Git status 禁用可选锁。用户提交创建表单或 Enter 进入时沿用现有归属、锁与资源准备逻辑。未知配置版本明确报错。

## 7. 实现组织

一个 Cargo 包；Ratatui 绘制，Crossterm 输入/终端恢复，Tungstenite 同步 WebSocket。模块：console/mod.rs（交互与生命周期），console/ui.rs（渲染），console/data.rs（采集与归属），codex.rs（服务发现与只读协议）。复用 registry/git/tmux，不拼接 Shell。

Console 在 Project::discover 之前分流；主窗口进入需独立支持，不能接管无归属的同名窗口。状态仅驻内存，不新增持久化数据库/用户配置。终端通过 RAII 在错误、正常退出、Ctrl+C 和 panic 时恢复。

## 10. 实施记录（2026-10-19）

已实现本方案的全局浏览、Shell 进入、查询线程、Codex 状态/历史/轮次和终端交互。新增 query.rs 专门限制采集线程命令；普通命令不受 2 秒超时限制。路径规范化和会话归属在采集线程完成，渲染只读内存快照。PgUp/PgDn 滚动详情。

新建项目 Session 的主窗口增加 @twig-feature=main 标记；已有无标记主窗口的复用同时核验所属 Session、main 名称和启动目录。不会接管同名的其他窗口。

实际 PTY 测试复现了 Crossterm 0.28 默认 mio 后端在缩放和输入同时到达时遗漏输入通知的问题。启用官方 use-dev-tty 特性，使用同步 poll 后端解决；没有增加专用事件线程或修改上游源码。终端恢复测试比较 termios 的输入、输出、控制、本地模式和控制字符，只排除内核瞬时 PENDIN 标志。

本机 0.163 CLI 的无提示词检查使用临时目录、临时信任覆盖参数和独立 tmux socket；未改真实信任配置、未发送提示词。进入 CLI 欢迎页尚未创建会话，因此 loaded/list 中没有对应记录；不能把“Codex 进程已打开”解释为已有会话。此前真实已存在的 active/idle 会话查询已成功。CLI 首轮开始后的状态流转未通过实际模型请求测试；等待审批、输入、轮次完成及断线重连通过模拟服务验证。

历史记录在后续完整 loaded 快照不再包含其 ID 时更新为「当前服务未加载」。历史查询刚返回的状态保留到下一轮采样；活动快照优先于同 ID 历史。轮次详情为按需快照，r 更新，不展示完整对话正文。

浏览不会操作真实项目；自动化测试全部使用临时 Git/配置、独立 tmux socket 和模拟 Codex 服务。尚未做 Linux 实机和真实 SSH 断网验收。

最终验证：cargo fmt --check、cargo clippy --locked --all-targets -- -D warnings、cargo test --locked 全部通过；共 45 个测试（8 个单元测试、5 个补全测试、6 个 Console 集成测试、8 个 PR/MR 测试、18 个工作流测试）。实际 Rust 客户端对本机 0.163 服务的只读冒烟检查成功：读取 2 个已加载会话、进行中的最新轮次、4 条 cwd 历史记录。数量仅为验证时快照。

本次未安装到用户 PATH、未修改用户 Shell 配置。可在仓库运行 cargo run --locked -- 体验，或按 README 安装后在任意目录运行 twig。

## 11. 控制台创建表单

项目区 n 登记已有 Git 仓库（路径、别名），任务区 n 新建任务（名称、已有本地起点分支，默认项目配置）；会话区 n 保留历史下一页。Tab 切字段、Esc 取消；登记路径字段 Enter 校验并默认填入主仓库目录名作为别名，别名字段 Enter 提交，任务表单 Enter 提交。成功后留在控制台并选中结果，不自动进入 Shell。

form.rs 管理表单与独立 twig 子进程：任务调用既有 new --no-open；项目使用隐藏的 __console-register 进程入口，复用 registry::initialize 与 init。cwd 变更只发生于子进程；已初始化仓库补登记、同路径复用、别名冲突不覆盖。不改变普通重复 init 的只读行为，不新增空仓库创建或远程克隆。

子进程参数逐个传递，stdin 关闭，输出写临时文件避免堵塞管道和打乱终端，主循环轮询完成状态。写操作不使用浏览查询的 2 秒超时，不强杀；执行期间禁止重复提交和退出，错误保留表单及已有资源。表单支持窄终端、长字段末尾可见及 PgUp/PgDn 滚动错误。

叠加后格式检查、Clippy 与全部 47 个测试通过。表单 PTY 测试及登记入口测试使用临时 Git 仓库、登记表和独立 tmux socket，覆盖取消、失败重试、带空格路径、成功留在面板、初始化补登记、路径复用和别名冲突。没有提交或安装本次表单功能。


控制台增加 Ctrl-W 前缀方向切区：h 回项目、l 从项目到任务、j 从任务到会话、k 从会话到任务；无相邻区域时不动，详情仍不单独获取焦点。前缀期间显示提示，后续非方向键仅取消前缀，Ctrl+C 仍可退出。搜索/表单/帮助中禁用；搜索不将 Ctrl-W 当作字母 w 输入。

列表首尾导航：项目、任务、会话列表均支持 gg 到顶部、G 到底部，基于当前筛选及已加载结果，不自动翻页。复用现有移动选择逻辑处理关联详情、历史与滚动状态；输入模式不启用，单 g 前缀用 Esc 取消。

### 搜索命令候选

输入 / 开启实时搜索与命令候选，不自动选中候选。支持 /new、/refresh、/help、/quit，前缀过滤，上下选择，Tab 补全；Enter 执行选中项或精确关键字，否则确认搜索。双斜杠强制文本搜索。输入前保存筛选与选择，Esc 取消或执行命令时恢复，避免关键词筛掉操作目标。表单输入不受影响；新建及其他原快捷键保留。具体交互见 [使用指南](console-usage.md)。验证更新为 50 个测试全部通过。

项目路径字段提供本地目录候选，仅扫描当前一级目录，在输入变化时更新。上下选择，Tab 补全（保留 /），无候选时切字段，Shift+Tab 总是切字段；路径字段 Enter 确认路径，别名字段 Enter 提交。支持 ~/、相对路径、空格及目录符号链接，点目录按点前缀显示，读取失败明确提示。目录补全与创建操作分离，不创建目录。叠加后格式检查、Clippy 与 51 个测试通过。

任务命名更新：任务名直接作为新分支名，支持 auth、feat/login、fix/bug，不添加固定前缀；控制台仍只有任务名和起点分支两个字段。Worktree 使用相应目录层级，窗口使用完整任务名。已有任务按原记录操作，不自动迁移。

### 任务删除

任务区 `/delete` 或 `dd` 打开默认取消的居中弹窗，保留控制台背景；标题、正文、按钮和提示居中对齐，内容可滚动，底部操作区固定。界面展示项目、任务、分支和 Worktree。Tab/左右键选择确认，空格切换保留分支并重置确认，Esc 取消。主工作目录不可删除。通过独立子进程调用 `rm --yes`，复用 CLI 的归属、文件、进程、合并与 upstream 检查；保留分支沿用 `--keep-branch` 语义，无 force。确认快照随隐藏参数传入，锁内重新核对仓库、分支与路径。

成功后强制刷新，收到任务已移除的新快照后选择主工作目录。失败保留界面和错误，重新确认后重试；写操作不强杀。采集器单独记录已处理的刷新序号，采集中到达的刷新请求留待下一轮处理。
