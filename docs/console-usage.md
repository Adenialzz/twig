# Console（控制台）使用指南

Console 是 twig 的全局终端面板，用来浏览已登记的项目、任务和 Codex 会话，并进入项目或任务的 Shell。它可以在 tmux 内外运行，占用当前终端界面，不会自动创建侧边 Pane。

## 1. 安装与打开

在 twig 源码目录安装或更新：

```sh
make install
```

随后在任意目录打开，不要求当前目录是 Git 仓库：

```sh
twig
twig console                # 与裸 twig 相同
twig --config ./config.toml    # 使用指定登记表
```

默认读取 `~/.twig/config.toml`。优先定位当前目录所属的已登记项目和任务，否则选择列表首项。

需要交互式终端，不能通过管道读取面板。脚本请使用 `twig ls` 或 `twig ls myapp`。

## 2. 让项目出现在面板里

面板只展示登记表中的项目，不会扫描磁盘。在左侧项目区按 `n`，填写：

1. **已有仓库路径**：支持绝对路径、`~/` 和相对路径；相对路径基于启动控制台时的目录。路径有空格时直接输入，无需额外加 Shell 引号。
2. **项目别名**：确定路径后默认填入主仓库目录名，可修改；使用字母、数字、横线或下划线，并以字母或数字开头。

路径字段会列出匹配的本地目录，按名称排序。`↑/↓` 选择，`Tab` 补全并保留末尾 `/`，可继续下钻；没有候选时 `Tab` 切到下一字段，`Shift+Tab` 始终切换字段。支持 `~/`、相对路径、空格和指向目录的符号链接；隐藏目录仅在当前目录名前缀以 `.` 开头时显示。补全只读取当前一级目录，不创建目录、不检查候选是否已初始化。读取失败显示原因，仍可手动输入。

路径字段按 `Enter` 先检查目录存在且属于非裸 Git 仓库，成功后切到别名字段并填入默认值；这一步不创建资源。完整目录优先，不会因存在子目录候选而误入下一级；输入尚未匹配完整目录时，先接受当前候选再检查。别名可以修改，也可以直接再按 `Enter` 完成登记。目录名含空格等不符合别名规则时，需手动修改。

除路径候选补全外，按 `Tab` / `Shift+Tab` 切字段；路径字段 `Enter` 确定路径，别名字段 `Enter` 提交；`Esc` 或 `Ctrl+C` 取消表单。登记不联网、不要求 remote。已初始化的仓库只补登记；未初始化的仓库会复用 `add` 的初始化流程，准备主窗口并登记。关联 Worktree 或子目录会定位到主仓库。同路径复用已有别名，别名指向其他路径时拒绝覆盖。

首次初始化要求仓库已有提交及本地 `main` 或 `master` 分支。其他起点请先在 Shell 中执行 `twig add NAME --path PATH --base BRANCH`。空目录创建和远程克隆暂不在表单中提供。

成功后自动选中项目并切换到任务区。也可以继续在 Shell 中使用 `twig add NAME --path PATH` 和 `twig ls`。

### 新建任务

选择项目，按 `Enter` 切到任务区，再按 `n`，填写：

- **任务名**：直接作为分支名，例如 `auth`、`feat/login` 或 `fix/bug`，不自动添加前缀；`main` 保留给主工作目录。
- **起点分支**：默认填入项目配置的基础分支，可改为其他已有本地分支，不会自动 fetch。

按 `Enter` 创建 Worktree、分支和任务窗口。成功后留在控制台并选中新任务，再按 `Enter` 才进入窗口。默认普通 Shell；配置了 `[tmux]` 时，创建窗口即启动指定的 Pane 命令，无需等待进入。项目与用户级配置规则见 [任务窗口初始化](../README.md#任务窗口初始化)。重复提交同名任务沿用 `new` 的接续规则，已有窗口不重复执行命令，不接管外部已有分支或目录。

### 执行中与失败重试

执行期间显示“正在执行”，表单暂不接受编辑或取消，避免强杀写操作留下锁。浏览查询的 2 秒超时不用于创建操作。字段或路径校验失败只显示具体原因；实际创建进程失败才提示已创建资源会保留。失败后保留输入和具体错误，修正后可再次提交；`PgUp/PgDn` 可滚动长错误。部分成功时保留资源，不自动删除回滚。

如果初始化已保存配置但后续失败，再次登记会补充登记表；缺失 Shell 窗口可在任务区按 `Enter` 准备。初始化/创建仍遵守原有归属检查和锁机制。

## 3. 看懂界面

宽终端共有四个可见区域：左侧为项目列表，右侧从上到下依次为任务列表、Codex 会话列表、详情。

| 区域 | 展示内容 | Enter 的作用 |
| --- | --- | --- |
| 左侧项目 | 项目别名、任务数量、Codex 状态摘要、异常 | 切到任务列表并选中「主工作目录」 |
| 右上任务 | 主工作目录及已登记任务、分支、Git 状态、tmux 窗口状态、Codex 摘要 | 进入所选任务的 Shell |
| 右中会话 | 当前任务目录关联的 Codex 会话；每行显示状态、ID 前 8 位和标题 | 读取所选会话最近一轮的状态，在下方详情区展示 |
| 右下详情 | 所选任务的路径、异常，以及所选会话的信息和最近轮次 | 不单独获取焦点，无独立 Enter 操作 |

`Tab` / `Shift+Tab` 只在项目、任务、会话三个列表之间切换焦点。详情随选择更新，用 `PgUp/PgDn` 滚动，无需先切入详情区。

也可使用 Vim 式两段按键：先按 `Ctrl-W`，再按 `h/j/k/l`（大小写均可）。`h` 回左侧项目；`l` 从项目进入任务；`j` 从任务进入会话；`k` 从会话返回任务。边界处保持原焦点，窄终端同样适用，不改变选中项。按 `Ctrl-W` 后底部显示方向提示，`Esc` 或其他非方向键取消本次前缀；该键不会同时执行其他操作。搜索、表单和帮助中不启用这组切区快捷键。

主工作目录不计入任务总数。项目和任务按名称排列；多个 Codex 会话分别列出，可通过 ID 区分。

默认隐藏 Codex 标记为 `ephemeral=true` 的临时会话，历史列表也不显示，状态统计不计入。此筛选只影响展示，不会删除或关闭会话，也不根据标题是否为空判断临时会话。

任务列表按表头对齐展示「任务、分支、Git、窗口、Codex」。任务区域不足 80 列时，每个任务显示两行，合并为「任务 / 分支」「Git / 窗口」「Codex」三列；过长内容在列内截断，不会挤乱后续列。

终端宽度不足 100 列时按焦点显示项目页、任务页或会话页，仍用 `Tab` 切换；会话页同时显示会话列表和详情。至少需要 38 列、12 行。

底部显示操作提示、Codex 连接状态或错误信息。正常刷新时不会显示跳动的秒数。

## 4. 常用操作

### 选择项目并进入任务

1. 在项目区用 `↑/↓` 选择项目。
2. 按 `Enter` 切换到任务区，默认选中「主工作目录」，再用上下键选择任务。
3. 按 `Enter` 进入其 Shell。

在项目区按 `Enter` 只切换焦点，并清除任务列表的搜索筛选；再按一次 `Enter` 才进入主工作目录。任务区按 `Shift+Tab` 或 `Esc` 返回项目区。进入前会重新核验配置和资源归属；窗口缺失时创建 Shell 窗口，Worktree 缺失时则报错，不自动重建代码。

从普通终端打开面板时，进入任务会 attach 到目标 tmux Session；按 `Ctrl+b`，再按 `d` detach 后，自动返回 Console，并保留项目、任务选择和焦点。此时按 `q` 才退出面板回到原 Shell。

从 tmux 内打开面板时，进入任务会切换到目标窗口，Console 留在原窗口，切回原窗口即可继续使用。此时 detach 是离开整个 tmux，不会切回 Console 窗口。

`exit` 会退出当前 Shell，可能关闭 Pane；如果希望保留任务环境并返回面板，应使用 detach。

### 快速跳到列表首尾

在项目、任务或会话列表中，连续按两次小写 `g` 跳到顶部，按大写 `G` 跳到底部。作用于当前筛选后的列表，不改变焦点；历史会话只在已加载的结果中跳转，不自动加载下一页。单按 `g` 时底部显示提示，`Esc` 取消，其他键取消前缀并按原功能处理。搜索或表单编辑期间，`g` 和 `G` 作为普通输入字符。

### 搜索

在需要搜索的区域按 `/`，输入关键词，列表实时筛选：项目匹配别名，任务匹配名称或分支，会话匹配标题或 ID。搜索开始时输入为空，原筛选及选择暂存；按 `Enter` 确认普通搜索并保留筛选，按 `Esc` 取消输入并恢复此前筛选和选择。退出输入后再按 `Esc` 才清空当前筛选。

输入框上方同时显示匹配的命令候选：

| 命令 | 操作 |
| --- | --- |
| `/delete` | 任务区删除选中任务，默认取消，可保留分支 |
| `/new` | 项目区登记已有仓库；任务区新建任务；会话区提示先切区 |
| `/refresh` | 刷新状态及已展开的轮次 |
| `/help` | 打开帮助 |
| `/quit` | 退出控制台，保留 Shell 和任务 |

候选按已输入前缀过滤，**默认不选中任何命令**。`↑/↓` 选择候选，`Tab` 补全所选候选（未选择时补全第一项），`Enter` 执行。未选中候选时，只有完整、大小写精确匹配的关键字触发命令；例如 `/ne` 按 Enter 仍搜索 `ne`，`/new` 按 Enter 才执行新建。

输入期间不执行命令。执行命令前会恢复原筛选与项目、任务、会话选择，避免输入关键字时把目标筛掉；原快捷键仍可用。

要搜索关键字本身，使用双斜杠，例如 `//new` 搜索文本 `new`，不显示命令候选。输入 `//` 后的所有内容都作为搜索词。

输入期间 `j`、`k`、`g`、`G`、`q` 等作为普通字符；上下键用于候选选择。`Ctrl+C` 在普通浏览和搜索时退出；表单编辑时取消表单，创建执行期间等待操作结束。

### 查看 Codex 会话与轮次

选择任务后切换到会话区，选择会话即可查看完整 ID、来源、模型、推理强度、创建/更新时间及父会话等信息。部分字段可能未提供；会话创建、更新时间固定显示北京时间（UTC+8），格式为 `2026-10-19 14:32:08`，不随系统时区变化。「更新」指 Codex 会话记录的更新时间，不是面板刷新时间。

按 `Enter` 加载最近一轮的状态、时间和错误，按 `PgUp/PgDn` 滚动详情。轮次详情按需读取，按 `r` 更新，不展示完整对话正文。

选择会话不会跳转到某个 Pane，也不会恢复对话或向 Codex 发送消息。

### 查看历史

1. 选择项目及任务，按 `h` 开启历史查询。
2. 默认查询与所选工作目录完全一致的历史，每页最多 50 条。
3. 按 `n` 继续加载下一页。
4. 如果 Codex 从子目录启动，按 `a` 开启包含子目录，再按 `n` 逐页继续扫描。
5. 再按 `h` 返回已加载会话视图。

包含子目录时，扫描进度统计的是检查过的记录数，不等于匹配会话数；某页没有匹配结果时仍可能有下一页。历史和已加载会话按 ID 去重，不会在启动时自动扫描全部历史。

## 5. 状态含义

### Git 与 tmux

Git 摘要显示暂存、修改、未跟踪文件数量，或「干净」。干净不包含 ignored 文件，也不代表已合并、已推送或可安全删除。

窗口状态来自 tmux。窗口存在只说明 Shell 环境存在，不能用来判断 Codex 是否正在运行。

### Codex

| 状态 | 含义 |
| --- | --- |
| 运行中 | 服务报告会话处于活动状态 |
| 等待审批 | 需要到原 Codex 会话中处理审批 |
| 等待输入 | 需要到原 Codex 会话中提供输入 |
| 空闲 | 当前没有活动轮次，不代表任务完成 |
| 当前服务未加载 | 当前连接的服务未加载此会话，不推断其他服务状态 |
| 会话错误 | 服务报告会话错误 |
| 未知 / 状态过期 | 查询失败或结果长时间未更新，不能据旧值判断当前状态 |

最近轮次的完成、失败或中断单独展示。轮次完成不等于开发任务完成。

### 自动刷新与过期提示

- 项目和任务记录：约每 10 秒更新。
- tmux 与 Codex 状态：约每 2 秒更新。
- 当前所选项目的 Git 状态：约每 5 秒更新。
- 历史与最新轮次：按需读取。

间隔从上一轮查询完成后计算。Git 或 Codex 超过 30 秒未成功更新会显示固定的「状态过期」，查询失败立即显示异常。按 `r` 可请求刷新。

## 7. 常见问题

**没有项目或任务？**

检查 `twig ls`、是否用了其他 `--config`，以及项目是否完成初始化。面板不自动发现未登记项目，也不把任意 Git 分支当作 twig 任务。

**项目可见，但进入失败？**

查看底部错误及详情中的工作区异常。缺失目录、分支变化、资源归属错误或同名窗口冲突都需要先处理，面板不会接管其他窗口。

**Codex 不可用，但项目正常？**

这是允许的。Codex 为可选功能，需要 PATH 中的 Codex CLI 和已运行的本机 app-server，首个实测版本为 0.163.0。面板不会启动或重启服务。可在 Shell 中用 `codex --version` 和 `codex app-server daemon version` 检查，再按 `r` 重试。

**Codex 已打开，却找不到会话？**

只覆盖当前服务可见的会话；独立服务或 `codex --no-daemon` 实例不保证可见。CLI 仅停留在欢迎页、尚未创建会话时也不会出现。会话按工作目录关联，目录不属于登记项目/任务时不会列入；历史从子目录启动的会话需开启包含子目录查询。未进入 Codex 状态数据库的历史记录也可能不可见。

**面板会修改什么？**

浏览只读，不创建配置、锁或窗口，不 fetch/pull/push。提交登记/新建表单时会创建对应资源；任务区按 `Enter` 准备并进入 Shell。删除任务可通过 `/delete` 确认执行；停止及 PR/MR 操作继续使用明确的命令，见 [README](../README.md)。

技术设计、协议与验证记录见 [Console 设计与实施方案](console.md)。

## 删除任务

在任务区选中任务，输入 `/delete` 并按 Enter，或直接按 `dd`，打开屏幕中央的紧凑确认弹窗，背景保留控制台。标题、正文、按钮和按键提示均居中对齐。长路径和错误区域可滚动，底部确认/取消按钮固定显示。单个 `d` 只显示待续提示，Esc 取消；其他键取消前缀后按原功能处理。搜索、表单和帮助中不启用 `dd`。主工作目录不能删除，项目区和会话区会提示切到任务区。

界面展示项目、任务、分支和 Worktree 路径。默认选中「取消」；Tab 或左右键切换到「确认删除」，Enter 执行，Esc 取消。↑↓ 或 j/k 选择「保留本地分支」或「同时删除被忽略文件」，空格切换勾选状态，切换后重新回到取消按钮；PgUp/PgDn 滚动长路径和错误。

默认删除任务窗口、Worktree、本地分支及任务记录，复用 `twig rm`，没有强制删除选项。默认存在未提交、未跟踪、ignored 文件或窗口活动进程时拒绝删除；删除分支还要求合并到项目目标，且相对本地 upstream 记录没有未推送提交。未配置 upstream 时只能验证本地合并，不代表远端已同步。勾选保留分支会跳过合并及推送检查，其他保护仍然生效。

执行前重新核对仓库、任务分支和路径；确认期间目标发生变化时拒绝操作，请取消并重新打开确认。执行期间不允许重复提交或强制取消。失败显示原因，可能已完成部分清理，修正后可重新确认重试。成功后刷新列表并选中主工作目录，留在控制台。删除不涉及远端分支，也不调用 Codex 接口。

### 同时删除被忽略文件

删除弹窗会列出 ignored 文件/目录，目录项代表目录内全部内容，可用 PgUp/PgDn 查看。默认不删除这些内容；用 ↓ 或 j 选中「同时删除被忽略文件」，按空格开启，随后重新选择「确认删除」。切换选项总会重置为取消。该选项不限于缓存，也可能包含 `.env` 或本地数据，需先核对清单。清单变化时拒绝删除，请取消并重新打开弹窗查看。

该选项只放行 ignored 文件；未提交、未跟踪文件、活动进程及原有分支检查继续生效。CLI 对应 `twig rm PROJECT NAME --delete-ignored`，会在确认前输出 ignored 清单；不使用 `git clean` 或 `worktree remove --force`。

选项区固定显示，当前选项整行高亮，`[x]` 表示已勾选。清单和错误在独立区域滚动，不会滚走选项和确认按钮。`i` 快捷键已移除。
